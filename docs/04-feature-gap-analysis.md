# 機能ギャップ分析（レガシーClient vs Pythonクライアント）

レガシーC++Builder製「Philly」クライアントとPython製 `~/workspace/phi-client` の機能差分。Webクライアント実装時の不足機能洗い出し。**描画周りは同等とみなし対象外**（ユーザー方針）。プロトコル・操作・ゲームロジック・周辺機能に集中。

調査方法: 両クライアントを並行精査（`legacy/client/Philly/` ＋ `phi-client/phi/`）。重要点は直接コード確認。

---

## 0. 総括

- **サーバ間移動（世界移動 `#ch-srv`）は Python実装済**。当初推測「未実装」は誤り。`network_thread.py` `_handle_ch_srv` にフルハンドシェイク（reserve→rsv-ok→trans→trs-ok→ch-srv-ok→接続スワップ→再ログイン）あり。**ただし永続化・タイムアウトに差分**（§3）。
- 真の不足は **チャットモード・戦闘自動化・キーバインド設定・BGM再生・通知・周辺ツール**。
- Python移植率は描画/マップ/接続/魔法ショートカットで高い（85〜90%）。残りは下表。

## 3. サーバ間移動（世界移動）の差分 ★要対応

ハンドシェイク本体はPython実装済だが、以下がレガシー比で**欠落・相違**:

| 項目 | レガシー | Python | 影響 |
|------|---------|--------|------|
| 待機タイムアウト | **300秒**（`TimeoutMs=300000`, PersonalThread.h:32） | **30秒**（`network_thread.py` `_wait_for_line` default=30.0） | 低速サーバで転送失敗の懸念。要300秒化 |
| **IDファイル更新** | ✅ `RewriteSaveData`→`ChangeServer(IP,Port)`で接続先を永続化（PersonalThread.cpp:195） | ❌ メモリ上`self._host/_port`のみ。プロファイル/設定へ未保存 | **再起動で移動先を喪失**。Web版はSQLiteの`characters.last_server`へ保存必須 |
| 移動ログ | ✅ `UpdateTransportLog("世界移動")`→Trans.log | ❌ | 任意 |
| 失敗時メッセージ | ✅ 詳細（手動書換要内等） | 🔶 簡易 | 任意 |

**Web版設計への反映**: 設計書`02`のSQLite `characters.last_server` は世界移動時に更新する。これがレガシーの`ChangeServer`（IDファイル書換）に相当。次回接続時は`last_server`を初期接続先に使う。

## 4. チャット送信仕様（詳細・要実装）

レガシーの発言は入力テキストへのプレフィックス付与で種別制御:

| 種別 | 送信形式 | トリガー |
|------|---------|----------|
| 通常 | テキストそのまま | Enter |
| 大声 | 先頭に `*` 付与 | 大声ボタンON / 確認ダイアログ |
| 大声無効化 | 先頭に `/**/` 付与（先頭が`*`の文を通常発言する場合） | 設定`LoudlyByAsterisk` |
| パーティー | （Ctrl+Enter）`PartyTalkByCtrl` | Ctrl+Enter |
| プライベート | `#priv <ユーザ番号>\n<本文>` | プリブウィンドウ |

→ Web版フロントは発言種別UI（通常/大声/パーティー/宛先選択）を持ち、バックエンドが上記形式に整形。`#priv`のユーザ番号は`#user`受信でマップ済（Python実装あり）。

## 5. Webクライアント実装への提言

1. **流用ベース**: Python `phi-client` のプロトコル/エンジン層をバックエンドへ移植（設計書`03` §5）。
2. **追加実装（高優先）**: 大声/パーティー/全タブ発言、pay、全自動攻撃・詠唱、more送信、s-edit入力UI。
3. **世界移動の永続化**: SQLite `last_server` 更新を必須化（§3）。タイムアウト300秒。
4. **BGM**: Web Audio。MIDIは変換要（midi→mp3/ogg事前変換 or Web MIDI）。優先度中。
5. **キーバインド設定**: Web設定画面でF1-F7魔法割当・ショートカットをカスタマイズ可能に。SQLite `settings`へ保存。
6. **通知**: タスクバーフラッシュ→ブラウザ通知API/タブタイトル点滅/音で代替。
7. **新規キャラ作成**: 専用Web UI＋バックエンドで再実装（別アプリ`NewCharacter`の置換）。
8. **対象外（描画）**: マップ/EagleEye/キャラ描画はPython同等で進める（ユーザー方針）。クォータービュー(isometric)はPythonでも未完のため任意。
